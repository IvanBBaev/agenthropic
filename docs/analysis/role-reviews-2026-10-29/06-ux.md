# agenthropic `apps/web`: UX / Frontend review (2026-10-29, read-only)

> Part of the [role reviews of 2026-10-29](README.md) — lens: **Senior Frontend Engineer & UX Designer (UX)**. Independent senior reviewer, read-only, on `main` at `db3f042`. Findings are de-duplicated and scheduled in [10-synthesis.md](10-synthesis.md).

## 1. Verdict

The SPA is careful about honesty and does it well. Unknown, unrecorded and unrecognised statuses, unpriced tokens, partial sessions, stale snapshots, SSE gaps and served-count disagreements are all rendered, never hidden. Loading, empty and error states exist in every view. The weak part is the core v1.0 promise of answering the five questions fast. The code does not implement the ux0 wireframes' fast paths:
- the Live board has no ATTENTION band;
- Live cards have no click-through to their tree;
- session trees are not live;
- the global DAG is a flat, left-packed layered SVG with no zoom, collapse, filter or search;
- Q2 and Q4 sit below the fold or are only partly answered.

The honesty prose has also grown to compete with the answer itself. Several views show 2–5 paragraphs of caveats before the chart, which works against the "<30s to understand a session" claim. Nobody has measured that claim.

**UX readiness for v1.0: 5/10.** The engineering is trustworthy, but the cockpit is not yet fast.

## 2. What is strong (with evidence)

- **The uncertainty vocabulary is a real design system.**
  - The status set has 5 states plus `unrecorded` plus `unrecognised("raw")` (`views/status.ts:32-135`).
  - The legend is generated from the same constants, so a glyph can never go unexplained (`Shell.tsx` `LEGEND_STATUSES` and `LEGEND_GAPS`).
  - Edges are drawn solid, dashed or dotted by provenance (`styles.css` `.edge-inferred` / `.edge-unrecognised`).
- **Cost is never a silent zero.** `formatUsd` prints `<$0.0001`, 4 decimals below one cent and an "unreadable" sentinel (`format.ts:89-96`). There is an `~` unpriced chip and column (`CostView.tsx:216-218`), and an `estimate` badge on savings (`CostView.tsx:1179-1184`).
- **Staleness is explicit and gets louder with age.** "Read X ago" turns into a warning banner once it is aged (`SessionsView.tsx:322-333`, `DagView.tsx:138-154`).
- **The connection chip is scoped and honest.**
  - It is labelled "event stream" (`Shell.tsx` `CONNECTION_SCOPE_LABEL`) and lives in a `role="status"` live region.
  - It tells "connecting" apart from "reconnecting" by whether the stream was ever open, and shows the attempt count.
  - `closed` gets a "reload" instruction, and unread or missed frames get their own chips.
- **Realtime correctness is solid.**
  - Live refetches after a reconnect (`LiveView.tsx:394-423`) and after frame-sequence gaps (`:371-385`).
  - It patches status buckets in place and refetches when an event does not match a known card (`:332-370`).
  - It tracks events missed while a fetch is in flight (`:253-302`).
- **Resilience.** There is a per-view `ErrorBoundary` keyed by route (`Shell.tsx` main). Unknown hashes are disclosed rather than silently swapped (`App.tsx` RT-1).
- **SVG accessibility baseline.**
  - Charts use `role="img"` with `aria-describedby` pointing at generated text summaries (`chart-summary.ts`, `SessionsView.tsx:358-404`).
  - Table alternatives exist for the sankey (Per model, Per day, Top burners, Top sessions).
- **Lean bundle.** One JS chunk, 309 KB raw / 94 KB gzip (`dist/assets/index-GuWMUQLT.js`). Only `d3-sankey` is imported, not all of d3. Status colours pass contrast on `#14161a`. There are 81 test files.

## 4. Five-questions scorecard

| Q | Screen today | Clicks / effort | Gaps |
|---|---|---|---|
| **Q1** Subagent tree + which branch is still running | Sessions → pick row → SVG tree | 2 clicks, plus memorising the session id from Live (no link) | Snapshot, not live (UX-3). Node $ and tokens are hover-only (UX-5). Wide fan-outs scroll horizontally (UX-4). No deep link (UX-1). |
| **Q2** Top burner + cost | Cost → scroll to section 7 "Top agent burners" | 1 click plus a long scroll | All-time slice of the newest 1000 agents. No today/week scope. The sankey is model→session, not agent (UX-7). |
| **Q3** Stuck/error unnoticed | Live (home) | 0 clicks, but you scan up to 50 cards | No ATTENTION band. Sorted by recency only. Ingest-failure banners are good (UX-2). |
| **Q4** Today/week cost + routing savings | Cost KPI strip (second row) | 1 click | Day boundaries are UTC. Savings is whole corpus only, with no windowed figure (UX-8). |
| **Q5** Last night's sessions, persisted | Live list (relative times); Sessions → "Changed since" date form | 0–2 clicks | No absolute timestamps or durations and no day grouping. 50-row cap with no paging (UX-6, UX-12). Persistence after restart itself works. |

All five can technically be answered. None meets the wireframe's "above the fold, <30s" bar as built. Q3 and Q1, the flagship flows, are the furthest from it.

## 5. Recommendations mapped to roadmap

**Before the v1.0 tag (≤2026-12-01):**
- **UX-1:** deep links and cross-links.
- **UX-2:** ATTENTION / RUNNING / RECENT partition.
- **UX-3:** live tree status.
- **UX-6 (UI part):** local start time and duration, day grouping.
- **UX-8:** local timezone and KPI order.
- **UX-7:** move Burners up and add a window toggle.
- **UX-9:** caveat chips with `<details>`.
- **UX-4, minimum:** session-grouped DAG with collapsed flat sessions, a range filter and pan/zoom.
- **UX-5, minimum:** visible tokens/$ on nodes.
- **UX-10:** amend ux0 §4.2 explicitly or ship it.
- **Then run the stopwatch protocol** (`docs/measurement/time-to-understand-protocol.md`) on the result. Without it, the release has nothing to stand on for the "<30s" claim.

**v1.x:**
- UX-5 in full: focusable nodes and agent detail panel.
- UX-6 in full: persisted session label and agent description.
- UX-11: Sessions IA cleanup.
- UX-12: paging and search.
- UX-13: responsive layout.
- UX-14: focus styles and skip link.
- UX-15: debounce refetches.
- UX-16: split CostView.
- UX-17: memoise layouts.
- Agent swim-lane / timeline view (every rival has one).
- A 5-hour quota / burn-rate window (offered by 4 of the 5 rivals).

**v2.0:**
- Alerts, which turn Q3 from pull into push and are already gated by KC-5.
- Transcript replay / per-agent event drill-down.
- Error-propagation highlighting in the tree.
- A light theme.

**Never:**
- A force-directed global graph.
- Type-aggregated agent diagrams (this contradicts the per-instance moat).
- Any browser-triggered action that spawns processes.

## 6. Questions for the owner

1. Should a session carry a human label (first user prompt, truncated, or the git branch)? Without one, "understand a session in <30s" depends on recognising UUIDs, and this requires a schema change.
2. Should "Today" follow local time (Europe/Sofia) or stay UTC? Is windowed delegation savings (today/7d) required for Q4 at v1.0?
3. Do you accept the ux0 ATTENTION / RUNNING / RECENT board as the v1.0 Live layout, replacing the pure recency list?
4. Is phone access over Tailscale a real use case? That decides whether UX-13 is P1 or P2.
5. For caveats: may the long-form honesty text move behind a compact chip plus disclosure, provided no fact is removed? Or is always-visible prose a hard requirement?
6. Should the global DAG show one row per session with flat sessions collapsed (as in ux0 §3c), and what default range: 24h or 7d?
7. Will you run the time-to-understand stopwatch protocol before tagging v1.0, and treat a fail as a release blocker?
