# Mutation score — baseline 2026-11-19 (QA-9)

A one-off [Stryker](https://stryker-mutator.io/) run (vitest runner, `coverageAnalysis:
perTest`) over the code whose numbers the dashboard claims as ground truth. Coverage
shows which lines **ran**; a mutation score shows which lines are **checked**: a
surviving mutant is a change to the code that every test still passes.

This is a **finding, not a gate**: there is no break threshold, CI does not run it, and
`RELEASE.md` §1 only asks that the next run before a tag be compared with this one.

| -------------------------------------------------- | -------------------------------- | ------: | -----: | -------: | -----: | ----------- |
| `packages/core` — parser, usage dedupe, cost       | `packages/core/stryker.config.mjs` |    1467 |   1312 |      150 |      5 | **89.74 %** |
| `apps/server` — API read models                    | `apps/server/stryker.config.mjs`   |     635 |    585 |       50 |      0 | **92.13 %** |

Run on a Mac Mini M4 under a load average of ~70–140 (other sessions building), Node
22.23.2, Stryker 10.1.1, two runners. Core took 1 h 51 min, the server 14 min 33 s. Wall-clock times are
therefore not a baseline; the counts are.

**Errors** are mutants Stryker could not judge (a `RuntimeError` in the test process,
not a test verdict). They are left out of the score, which is `killed / (killed +
survived)`.

## How to repeat

```sh
pnpm --filter @agenthropic/core mutation     # then, not in parallel:
pnpm --filter @agenthropic/server mutation
```

Both mutate the source **in place** (sandbox mode breaks a test that walks `../../../`
to the repo root), so they must not run at the same time, and a killed run must be
followed by `git checkout -- src` and `rm -rf .stryker-tmp` in that package (a
leftover `.stryker-tmp/` holds copied tests that Vitest picks up and a `node_modules`
link that `gate:spawner` refuses). Reports land in
`<package>/reports/mutation/mutation.json` (git-ignored).

### 1. Gaps worth a test (candidates for follow-up)

- **`format-census.ts` L35–L78 — the known-type tables (30 survivors).** Blanking any
  entry of `KNOWN_RECORD_TYPES` (`agent-name`, `ai-title`, `attachment`, `cost-state`,
  `file-history-snapshot`, `launched`, `pr-link`, …) or of the known usage keys
  (`fallback_credit`, `iterations`, `output_tokens_details`, `server_tool_use`) passes
  every test. Nothing asserts that each known type is **not** reported as unknown, so a
  dropped entry would put a false "unknown record type" line in the census. One
  table-driven test over the exported sets kills the whole group.
- **`format-census.ts` L219 — `>` vs `>=` on `MAX_DIMENSION_VALUE_LENGTH`.** No test
  sits on the exact truncation boundary.
- **`format-census.ts` L183 — empty `version` string.** A record with `version: ''`
  is never fed in; it should count as unversioned.
- **`parse-session.ts` L84–L88 — filename regex anchors.** `AGENT_FILE_RE`,
  `AGENT_META_RE` and `WORKFLOW_DIR_RE` keep passing with `^` or `$` removed: no
  fixture has a name like `xagent-ab.jsonl`, `agent-ab.jsonl.bak` or `my_wf_dir`.
- **`parse-session.ts` L1034–L1039 — the usage-owner index guard.** The whole
  "assistant record with an id and a usage block" filter can be removed. No fixture has
  a usage-less assistant record whose `message.id` also appears in another transcript,
  which is the case the filter protects in fork dedupe.
- **`parse-session.ts` L1189 — fork-parent recording.** The `parentAgentId !== null`
  half of the condition is never exercised (no fork whose parent is unresolved).
- **`parse-session.ts` L462–L592 — tool-result / tool-use / progress linking (≈35
  survivors).** Most are `if (x !== undefined)` guards turned into `true` and
  `block.type !== 'tool_result'` filters turned into `false`. They survive because the
  fixtures never mix a non-matching block or an id-less block into the content arrays
  that these loops scan. Malformed-content fixtures would kill most of them.
- **`compaction.ts` L57, L91, L115 and `cost-state.ts` L62–L72 — local type guards.**
  `isJsonRecord`, the non-negative integer/number guards and the `preTokens` finite
  check pass with their conditions forced to `true`: the tests never hand these modules
  an array, `null`, a negative or a non-finite number where an object or a count is
  expected.

### 2. Untested message text (low value)

- `name = 'PricingError'`, `'UsageConflictError'`, `'SubstrateError'` — no test asserts
  `error.name`.
- Error and warning message templates (`compute-cost.ts` L67, L125; `parse-session.ts`
  L1170, L1192; `compaction.ts` L101 `index + 1` → `index - 1`, i.e. the reported line
  number). Tests match on the error class or a fragment, not the full text.

### 3. Equivalent or near-equivalent mutants (no test can or should kill them)

- **Optional chaining on values that are never nullish** (≈20, e.g. `record?.['message']`
  → `record['message']` where `record` comes from a non-null parse). The `?.` is
  defensive typing, not behaviour.
- **Blank-line skips** (`compaction.ts` L82, `parse-session.ts` L188): removing the
  explicit `line.trim() === ''` check still skips the line, because `JSON.parse` throws
  on it and the catch skips it too.
- **Tie-breaking boundaries**: `dedupe.ts` L152 (`>` → `>=` when two usage values are
  equal picks an identical value), `parse-session.ts` L931 (equal timestamps) and L994
  (`unsplit > 0` → `>= 0` when zero is left to split).
- **`compute-cost.ts` L95 and L136.** Dropping the `break` in `resolveRate` only keeps
  scanning rates that are sorted by `effectiveFrom` and can no longer match. Forcing
  `promptLimit !== undefined` to `true` compares `promptTokens > undefined`, which is
  always `false`, so no model without a limit is ever refused.
- **Empty-collection defaults**: `?? []` → `['Stryker was here']` at
  `parse-session.ts` L520 and L704, where the default is only reached for a key that is
  then never looked up again.

### 4. Errors (5)

`parse-session.ts` L349, L538, L543 (optional chaining removed) and L569 (two
condition mutants) throw a `TypeError` in the test process before any assertion runs.
Stryker reports them as `RuntimeError` and leaves them out of the score; in practice
the mutation is caught, just not by an assertion.

### 1. Gaps worth a test (candidates for follow-up)

- **`savings.ts` L431–L432, L443 and `changes.ts` L515–L516 — fixed DTO fields.**
  `isEstimate: true` → `false`, `basis: 'stored-usage-rows'` → `''`, `interval:
  '(since, until]'` and `basis: 'event-time'` → `''`, and dropping the sort of
  `hypotheticalModels` all pass. These are contract fields the UI and the docs rely on
  (the savings figure is labelled an estimate because of `isEstimate`); no test pins
  them.
- **`changes.ts` L352 — `lateIngested.next`.** The cursor arithmetic survives four
  mutants. No test reaches the rewound-clock case the comment describes (an `after`
  above the cursor, i.e. a database restored from an older backup), nor a complete page
  whose last row sits below the cursor.
- **`changes.ts` L128 — the `until` clamp.** No test has every stored instant older
  than `since`, the case that clamps the window end to `since`.
- **`savings.ts` L282 — `UNSTAMPED = -1` → `+1`.** The sentinel's job is to never match
  a real `ingest_seq`; `+1` would, and no test has a session stamped `1` next to an
  unstamped one.
- **`cost.ts` L93 — the non-negative finite guard** passes with its condition forced
  to `true`: no stored value it guards is ever negative or non-finite in the tests.

### 2. Defensive invariants and message text

- **`changes.ts` L188–L211, L314, L555.** `assertChangesInvariants` checks that a
  computed answer is internally consistent and throws if it is not. Its labels can be
  blanked and the call itself removed because no reachable input produces an
  inconsistent answer: it guards a bug, not an input. Killing these would need a test
  hook into the read model's internals, which is not worth it.
- **`cost.ts` L111, L112, L136** — refusal message text.

### 3. Equivalent or near-equivalent mutants

- **Empty-list short-circuits** (`changes.ts` L438, `sessions.ts` L241, `cost.ts`
  L488–L489): without them the follow-up query runs with an empty id list and returns
  no rows, so only a query is saved.
- **`cost.ts` L148 `byBinary`** — `<` → `<=` cannot matter: every caller sorts unique
  `Map` keys (the function's own comment says so).
- **`cost.ts` L60** — the `\u0000` join separator of a lookup key; `''` only collides
  for model/bucket/date triples that run into each other, which no real model id does.
- **`dag.ts` L196** — optional chaining on a usage map that always has the session.
- **`savings.ts` L183, L203–L204, L210, L252, L259, L368** — initial values of the
  synthetic parse result the savings model builds from stored rows (empty arrays,
  placeholder timestamps, the `kind` tag, an optional field passed as `undefined`).
  None of them reaches the reported figures. These were not each traced to the line;
  they are listed so the next run can tell whether the set changed.

## Follow-up

The baseline numbers above stay as they were measured; later work that closes a gap
is listed here, so the next run before a tag can be compared with both.

- **QA-9a — core census and filename patterns.** Tests in
  `format-census.test.ts`, `classify-relative-path.test.ts` and
  `self-parent-guard.test.ts` cover the group-1 gaps of `format-census.ts` and the
  `parse-session.ts` filename patterns: a literal list of the known record types and
  usage keys, the `(missing)` / `(none)` keys, a value of exactly 64 characters, an
  object value, `version: ''` and a non-string version, pre-version drift attributed
  to the first version rather than the last, usage read only on assistant records,
  the `^` / `$` anchors of `AGENT_FILE_RE` and `AGENT_META_RE`, and the `wf_` prefix
  of `WORKFLOW_DIR_RE` (`my_wf_x/` is not a workflow directory). Each of these
  mutants was applied by hand and fails the suite. Not rerun under Stryker. The
  `[\s\S]` → `[\S\S]` mutants of `TOOL_USE_ID_RE` / `TASK_ID_RE` are left as
  near-equivalent: a real tool-use or task id never contains whitespace.
- **QA-9b — server read models.** Tests in `api-aggregate-savings.test.ts`,
  `api-aggregate-savings-cache.test.ts` and `api-changes.test.ts` cover the group-1
  gaps: `isEstimate` / `basis` (savings) and `interval` / `basis` (changes) asserted on
  the read model directly — the HTTP tests could not kill them because the response
  schema declares these fields as literals and the serializer writes the schema's
  constant; the `hypotheticalModels` sort, with a session met first whose model sorts
  between the others; `UNSTAMPED` against a session stamped `1`; `lateIngested.next`
  on a complete page whose last row sits below the clock (kills `<` → `<=`,
  `&&` → `||` and `rows.length < total` → `true`); and the `until` clamp for a `since`
  beyond the corpus. Each of these mutants was applied by hand and fails the suite.
  Not rerun under Stryker. Left as equivalent: `cost.ts` L93 — forcing the whole
  guard to `true` was already killed by `api-served-honesty.test.ts`; the survivor is
  `typeof value === 'number'` → `true`, which `Number.isFinite` (no coercion) makes
  redundant at runtime; and `changes.ts` L352 `last !== undefined` → `true`, reachable
  only with `limit = 0`, which the route refuses (`minimum: 1`). The rewound-clock case
  (`after` above the cursor) is already covered by the restored-backup test: its window
  is empty, so `next` is the cursor under every mutant.
- **QA-9c — core linking guards, usage-owner index, local type guards.** Tests in
  `linking-guards.test.ts`, `extract-compaction-boundaries.test.ts` and
  `cost-state.test.ts` close the remaining `parse-session.ts`, `compaction.ts` and
  `cost-state.ts` group-1 gaps with decoy shapes: an `is_error` on a non-`tool_result`
  block (L468), an `Agent` name on a non-`tool_use` block (L508), an id-less `Workflow`

  1-based line number in the missing-timestamp error (L101), and a `null` or numeric
